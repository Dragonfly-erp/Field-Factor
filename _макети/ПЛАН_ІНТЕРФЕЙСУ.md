---

## 1. Чому переробляємо

Поточний екран не читається як агрософт. Конкретно:

1. панель операцій — плаваюча картка **поверх карти**, обрізана зверху й знизу;
2. плейсхолдер «Тут буде поле» світиться **поверх намальованих зон**;
3. ліва колонка обрізана по горизонталі — сторінка має горизонтальний перетік;
4. легенда — головне, заради чого дивляться на карту — показана в щілину;
5. немає ієрархії: вісім операцій однакової ваги, усі заголовки капсом;
6. немає стану роботи: не видно, на якому ти кроці й чим це закінчиться.

**Головна вимога Власника:** видно **весь ланцюг** — від початку до кінця,
щоб людина розуміла, **чим закінчиться її робота** і які кроки для цього
треба пройти. Софт стає **складнішим і насиченішим**, а не простішим.

## 2. Каркас екрана

```text
+--------------------------------------------------------------------------+
| FieldFactor   Клієнт · Господарство · Поле Ж 03 · 41,9 га · UTM 35N       |  шапка
+--------------------------------------------------------------------------+
|  ВХІДНІ > ПІДГОТОВКА > ЗОНИ > ЗРАЗКИ > ПЕРЕВІРКА > ВИДАЧА                 |  ряд 1: ланцюг
+--------------------------------------------------------------------------+
|  [ Мета ]  [ Джерела ]  [ Налаштування ]  [ Результат ]                   |  ряд 2: підтаби
+---------------+--------------------------------------+-------------------+
| ДЕРЕВО        |                                      | ІНСТРУМЕНТИ ШАРУ  |
| інформації    |                                      | і налаштування    |
|               |              К А Р Т А               |                   |
| клієнт        |                                      | показ · легенда   |
| |-господарство|     (центр, ніколи не рухається)     | прозорість        |
|   |-поле      |                                      | класи · розбиття  |
|     |-вхідні  |                                      | фарбувати за…     |
|     |-операції|                                      |                   |
|               +--------------------------------------+                   |
| +-----------+ | КОНТЕКСТ: активний шар, доступні     |                   |
| |  прев'ю   | | шари для порівняння, чесність        |                   |
| +-----------+ |                                      |                   |
+---------------+--------------------------------------+-------------------+
```

**Правила каркаса:**

- карта в центрі й **ніколи не змінює розмір** — панелі не «наїжджають» на
  неї, ширина колонок стала;
- **обидва ряди табів угорі**, над робочою областю (рішення Власника);
- ліва колонка — **навігаційне дерево інформації + прев'ю** знизу, як у
  SMS Ag Leader: клацнув вузол — у прев'ю мініатюра того, що це;
- права колонка — **інструменти керування активним шаром і налаштування**;
- смуга під картою — **контекст**: що зараз активне, які ще шари є для
  порівняння, наскільки цьому вірити;
- тема **світла**, щільна, професійна. Колір — на карті, панелі сірі.

## 3. Ланцюг: шість кроків

Ланцюг видно завжди й цілком. Крок, для якого немає даних, **не ховається** —
він пригашений і підписаний причиною: «немає файлів монітора».

### Крок 1 · ВХІДНІ

Те, що приніс клієнт. Нічого не втрачається.

| Підтаб | Що робить |
|---|---|
| Папка поля | У кожного поля є тека **Вхідні дані**. Можна скинути туди все як є |
| Імпорт із розпізнаванням | Перетягнув файл — програма каже, що це, і показує розбір |
| Майстер | Розбирає те, що лежить у папці, з підказками. Не впізнало — питає людину, відповідь запам'ятовується для таких самих файлів |
| Дерево операцій | Куди що лягло: операція, рік, дата, обсяг |

**Правило:** сире лишається у «Вхідних даних» назавжди й недоторканим.
Упізнане не «перекладається в розібране» — воно **приписується до операції**
на цьому полі (розділ 7). Окремої купи «розібране» в дереві немає.

### Крок 2 · ПІДГОТОВКА

Привести сире до придатного стану.

| Підтаб | Що робить |
|---|---|
| Врожайність | Нормалізація з монітора комбайна, зведення кількох комбайнів, відкинуті записи з причиною |
| Сканування | Вирівнювання по проходах сканера, мертві канали, суфікс `_ВИПР` — сирі числа лишаються недоторканими |
| Знімки | Багаторічний пік NDVI, яскравість голого ґрунту |
| Рельєф | DEM, схил, положення в околиці |

### Крок 3 · ЗОНИ

Серце програми.

| Підтаб | Що робить |
|---|---|
| Мета | Два рівні (розділ 4) |
| Джерела | Що допущено цією метою і з якою вагою |
| Налаштування | До восьми важелів (розділ 5), пресети |
| Результат | Карта, легенда, площі зон, різниця з іншими картами |

### Крок 4 · ЗРАЗКИ

| Підтаб | Що робить |
|---|---|
| План відбору | Точки в серцевині зон, групи |
| **Завдання на відбір** | Формує завдання для того, хто поїде брати зразки: точки, номери, до якої зони належать, маршрут. Вивантаження **SHP** (термінал) і **KML** (телефон, навігатор, Google Earth) |
| Занесення аналізів | Excel / CSV або руками у свою таблицю |
| Прив'язка | Зразок належить або точці, або зоні |

**Завдання на відбір — це окремий продукт, а не побічний файл.** Воно має
жити в дереві поля з датою й номером, щоб через рік було видно, за яким
саме завданням брали ті зразки, які потім прийшли з лабораторії.

### Крок 5 · ПЕРЕВІРКА — **в розробці**

Власник поки не вирішив, що тут буде. Крок існує в ланцюзі й чесно
підписаний «в розробці». Кандидати, названі Власником:

- чи тримаються зони роками (ті самі зони на даних різних років);
- чи розділяють зони аналізи ґрунту — розкид **між** зонами проти розкиду
  **всередині** зони. Саме це відповідає на питання «чи є сенс зонувати
  під калій».

### Крок 6 · ВИДАЧА

Окремі підтаби всередині головного таба:

| Підтаб | Що віддаємо |
|---|---|
| Термінал | Шейпфайли під SMS Ag Leader |
| Звіт | Документ для господарства (жанр «Г» із макета) |
| Навігатор | Точки відбору: **SHP і KML** |
| Завдання на відбір | Те, що зібрано на кроці «Зразки», готове до передачі в поле |
| Пакет | Усе разом архівом, одним файлом |

## 4. Мета зонування — два рівні

### Верхній рівень: що це за робота

| Режим | Що це |
|---|---|
| **Дослідження поля** | Основний. Поле ділиться за даними, які є: знімки · +сканування · +карти врожайності. Набір обирає користувач — це **не «рівні»**, а просто набори |
| **Точкове** | Ретроспектива. Перевірити конкретні місця, де вже брали зразки: що там було й що з того вийшло |

### Нижній рівень: під що саме

**Вапнування · НПК · Посів.**

### Що саме міняє мета

Не тільки ваги — це важливо, бо зараз у програмі мета крутить **лише** ваги,
і це напівправда:

| Що міняється | Приклад |
|---|---|
| допущені джерела | під вапнування врожайність не свідок |
| ваги джерел | під посів веде рельєф і вода |
| кількість зон | під внесення можна дрібніше, ніж під відбір |
| мінімальна площа | авто 1 га або вручну |
| що є виходом | шейп у термінал · точки · документ |

### Позиція про агрономічну підставу

Записано, щоб не переобговорювати:

- **врожайність не показує, чим ґрунт здатен нагодувати.** Це наслідок, у
  якому змішані погода, гібрид, хвороби, ущільнення. Рахувати з неї винос
  і досипати — це те саме «слабка зона = сипати більше», вивернуте навиворіт;
- **норму дає аналіз ґрунту з зони, а не карта.** Карта каже, де брати зразок;
- сила підстави по елементах різна: **вапнування** — найсильніша (буферність
  = глина й гумус, а це стабільні властивості, які EC і яскравість міряють
  фізично); **калій** — середня (K тримається на глині й ЄКО); **фосфор** —
  слабка (плямистий, керується історією внесення); **азот** — окремий випадок
  (рухливий, у зоні не лежить);
- **довести це на даних зараз нічим** — немає жодного поля з аналізами по
  зонах. Доки кейсу немає, програма не має права стверджувати, що зони під
  калій щось означають. Це питання кроку «Перевірка».

**Змінене рішення:** прив'язку аналізів ґрунту до зон було відкладено
2026-08-19 через відсутність кейсу. Точковий режим повертає її в роботу.
Зміну треба записати в `STATE.md` явно, а не тихцем.

## 5. Налаштування зон: до восьми важелів

Орієнтир — панель зі знімка Власника, але глибше й із поясненнями.
Кожен важіль підписаний тим, **що він робить і чим ризикує**.

| # | Важіль | Значення |
|---|---|---|
| 1 | Джерела і ваги | що ріже поле й наскільки сильно |
| 2 | Кількість зон | мін · бажано · макс |
| 3 | Метод розбиття | квантилі · рівні інтервали · природні розриви |
| 4 | Мінімальна площа | **авто 1 га** або вручну |
| 5 | Згладжування меж | наскільки згладжувати контури зон |
| 6 | Розмір комірки | крок сітки розрахунку |
| 7 | Викиди | відкидати чи лишати |
| 8 | Відступ від межі поля | щоб зона не ліпилась до краю |

**Пресети:** базові (від нас) і користувацькі (глобальні, доступні на
будь-якому полі). Плюс кабінет — особисті налаштування способу роботи.

## 6. Карти зон на полі

- одночасно **від 2 до 10** карт;
- кожна підписана метою, датою й набором джерел;
- програма показує **числом**, наскільки дві карти різні: частка площі,
  яка потрапляє в іншу зону.

---

## 7. Дерево управління господарства

**Усе, що програма породила, лягає назад у дерево — до свого поля.**
Не в теку завантажень, не «куди вкаже діалог збереження». Вихідні масиви
такий самий актив господарства, як і вхідні: через рік має бути видно, що
саме віддали клієнту і з чого воно пораховане.

**Одиниця класифікації — операція**, як у SMS Ag Leader
(Grower → Farm → Field → Operation → Operational Instance). Окремого вузла
«розібране» немає: щойно файл упізнано, він лягає до **своєї операції** на
**своєму полі**. Одна операція може мати кілька екземплярів — по роках і датах.

```text
Клієнт (Grower)
 └─ Господарство (Farm)
     └─ Поле (Field) · Ж 03
         ├─ Вхідні дані                    сире, як приніс клієнт, недоторкане
         └─ Операції
             ├─ Контур поля
             │   └─ 2019
             ├─ Сканування ЕМ (EC + RTK)
             │   └─ кв. 2025 · 6 854 точки
             ├─ Збирання (врожайність)
             │   ├─ 2025 · 24 проходи
             │   └─ 2026
             ├─ Зони керування
             │   ├─ під вапнування · 12.08.2026
             │   └─ під посів · 14.08.2026
             ├─ Відбір ґрунту
             │   ├─ Завдання №14 · 15.08.2026 · SHP + KML
             │   └─ Аналізи по завданню №14 · 02.09.2026
             ├─ Посів                      сховище: рахунків не робимо
             │   └─ 2026 · файл із терміналу
             └─ Видача клієнту
                 └─ пакет · 20.08.2026
```

**Три рівні над полем — рішення Власника.** Дерево збігається з тим, у чому
клієнт уже працює (SMS Ag Leader: Grower → Farm → Field), тому обмін даними
не вимагає перекладу структури.

**Правила дерева:**

- **немає вузла поза операцією.** Файл, який не вдалося віднести до операції,
  лишається у «Вхідних даних» зі статусом «не розібрано» — і це видно;
- кожен екземпляр несе **дату, походження й статус** — без цього число
  в звіті не має підстави;
- вихідні масиви **не перезаписуються мовчки**: новий розрахунок стає новим
  екземпляром, попередній іде в історію;
- завдання на відбір і аналізи, що по ньому прийшли, **пов'язані між собою** —
  саме цей зв'язок робить можливим точковий режим і крок «Перевірка»;
- ліва колонка інтерфейсу — це і є **вигляд цього дерева**, а не окремий
  список шарів.

### Перелік операцій — чернетка

Остаточний список складає Власник. Нижче — чернетка під те, що програма
справді вміє й віддає:

| Група | Операції |
|---|---|
| Основа поля | Контур поля · Висотна модель (рельєф) |
| Виміри | Сканування ЕМ (EC + RTK) · Супутниковий знімок · Багаторічна вегетація · Яскравість голого ґрунту |
| Роботи господарства | Збирання (врожайність із монітора) · Посів · Внесення · Обприскування · Вапнування |
| Наші продукти | Зони керування · Відбір ґрунту (завдання + аналізи) · Полеве випробування · Видача клієнту |

**Операції-сховища.** Посів, Внесення, Обприскування ми не рахуємо — але
господарство їх дає, і в дереві вони мають своє місце. Заводимо як
**сховище**: файли лежать, підписані датою й походженням, показуються на
карті шаром, у розрахунок не входять. Коли з'явиться робота з ними —
операція вже є і дані вже зібрані, нічого не доведеться шукати заново.

## 8. Стани — те, що зараз зламано

| Стан | Що на екрані |
|---|---|
| Немає жодного поля | Карта на локації з налаштувань, тло — супутник. Жодних «тут буде поле» поверх даних |
| Поля є, жодне не обране | **Усі поля господарства на карті** одразу |
| Поле обране | Дерево ліворуч, шари, карта на полі |
| Крок без даних | Пригашений, з причиною й запрошенням завантажити |
| Розрахунок іде | Прогрес у панелі кроку, карта лишається живою |

**Правило:** порожній стан ніколи не малюється поверх непорожнього.

## 9. Тло карти

Супутникові плитки з інтернету — **дозволено** (рішення Власника).
Питання джерела плиток і його ліцензії лишається технічним і вирішується
окремо.

---

## 10. Чого не робимо

- не чіпаємо піксельний фільтр аномалій EC — він навмисне лишений
  попередженням, справжню роботу робить вирівнювання по проходах;
- не копіюємо дані господарств із `farms\` у теку продукту;
- не вигадуємо вміст кроку «Перевірка» замість Власника;
- не робимо режим «зони під внесення елементів» готовим продуктом, доки
  немає кейсу з аналізами по зонах.

---

## 11. Відкриті питання

1. Що саме стоїть у кроці «Перевірка».
2. Джерело супутникових плиток і його ліцензія.
3. Чи потрібен окремий польовий екран для планшета (варіант «Б» із макета)
   і коли.
4. Чи лишається «Засолення» як окрема мета — у розмові прозвучало
   «не актуально», але прямо не знято.
5. **Перехід на три рівні.** Наявні дані лежать у двох (господарство → поле).
   Треба вирішити, чим заповнюється новий верхній рівень для того, що вже
   заведено: одним клієнтом за замовчуванням чи руками при першому відкритті.

## 12. Рішення 19.08, вечір

Після двох рецензій і розбору протоколу лабораторії.

**Методи аналізу.** Чирікова й Мачигіна не існує і не буде. Тільки Bray, Olsen,
Mehlich-3. Який метод фосфору чинний — вирішує pH ґрунту: Bray на кислих і
нейтральних, Olsen на карбонатних. Порівнювати їх між собою заборонено.

**Глибина відбору** — 30 см за замовчуванням, з нашого завдання, не з протоколу.

**Норми звужені до вапнування.** Метод Зеленої Поляни: дефіцит насиченості
основами × ЄКО × маса шару; рішення «вапнувати чи ні» через відстань pH до
порога у σ методу з вироком СТІЙКЕ / НА МЕЖІ / ВИПАДКОВЕ; ворота «кальцій
витісняє калій». Входи виміряні лабораторією, а не виведені: буферний pH за
Sikora, ЄКО, насиченість основами, щільність ґрунту.

**Бенди забезпеченості, балансування, співвідношення Ca:Mg:K — поза обсягом.**
Це рекомендації, окрема історія, зараз не чіпаємо.

**Рівні забезпечення ХАНЗЕ** використовуються тільки для розфарбування
показників аналізу на екрані. У розрахунок норми не входять.

**Метод форкається в продукт із провенансом** — за прямим дозволом Власника.
У скопійоване кладеться версія й коміт джерела з майстерні, щоб пізніше можна
було звірити діф.

**Точка = проба. Зразок = багато проб або точок** — по маршруту або в межах
зони. Завдання на відбір малює маршрут або набір точок, які зсипаються в один
зразок.

**Додається відбір за сіткою** — класична, динамічна із заданим розміром
комірки, і коригування контурів комірок на рельєф, вегетацію, врожайність або
сканування.

**Не робимо:** калібрування монітора по вазі окремим кроком (звірка лишається
як є); історію внесення й гній.
