Головне правило: поки екран не побачений у браузері — він не зроблений.
Уточнення від 19.08: **клацати треба справжнім клацанням по координатах**,
а не викликом `.click()` з консолі. Виклик перевіряє функцію, клацання —
інтерфейс. Саме на цій різниці ховався вчорашній баг.

**Проєкт.** FieldFactor — портативна програма для агрономічного консалтингу.
Тека `C:\WORK D\agroplace-farms\FieldFactor\`, власний git, репозиторій
`Dragonfly-erp/Field-Factor`. Запуск: `ЗАПУСК.bat` → браузер на `127.0.0.1:8756`.
Робить зони керування, файли під SMS Ag Leader і звіт для господарства.
У `.bat` тільки латиниця — кирилиця ламає розбір cmd.

**Зламаного немає.** Вікно зонування полагоджено: причиною була не помилка
в JS, а `.накладка { display: flex }` без `.накладка[hidden] { display: none }` —
накладка висіла поверх сторінки й ковтала всі клацання. Заодно статика
(`/web/*.js`, `.css`) тепер віддається з `Cache-Control: no-store`, бо
програма оновлюється на місці й браузер лишав вчорашній скрипт.

Пройдено руками і підтверджено: вибір поля, вікно зонування (6 цілей,
5 джерел), побудова зон до записаних файлів `зони_рельєф_2026_відбір.*`,
показ розбору сканування (5231 точка, 3 канали, 35 проходів).

`_макети\ЗАВДАННЯ_НА_ДИЗАЙН.md`. До того оформлення не чіпати.

**Чого не робити:** не братись за прив'язку аналізів ґрунту до зон

вирівнювання по проходах); не копіювати дані господарств із `farms\`

шару питається через `prompt()`. Працює, але це не вікно продукту —
чіпати разом із дизайном, не раніше.
